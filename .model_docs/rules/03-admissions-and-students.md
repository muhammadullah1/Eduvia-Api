# Admissions and students

Sources: SRS §4.3, P1-02, P1-03.

## Admission chain

An application is not a student until enrollment.

`Student details → Guardian → Documents → Interview / test → Decision → Enrollment`

| Step | Required by the working product | Stored |
|---|---|---|
| Student | Name, date of birth, gender, class applied for | Applicant name, gender, dob, grade |
| Guardian | Guardian name and phone | Parent name, email, phone |
| Documents | Tracked, not all mandatory | Pending, Uploaded, or Verified |
| Interview | Optional until the school says otherwise | Date, type, score, remarks |
| Decision | Admit, Reject, or Waitlist | Decision plus notes |
| Enrollment | Only after Admit | Creates the student in a class of the current session |

### Application status

Use these values. Do not use the unused migration set `Inquiry / Applied / UnderReview / InterviewScheduled / Approved`.

| Status | When |
|---|---|
| `New` | Just captured |
| `Review` | Decision is Admit, not yet enrolled |
| `Waitlist` | Decision is Waitlist |
| `Rejected` | Decision is Reject |
| `Enrolled` | Student row created |

Enrollment requires decision `Admit`. It creates an `Active` student in the chosen class and session, on the enrollment date, with a unique admission number. Withdrawn is a student status after enrollment, not a way to skip the decision.

The baseline also allows enrollment status Pending at the moment of joining. The live student statuses below are the contract until the school asks for a separate enrollment status.

## Documents

Each document has a title, a type, and a status: `Pending`, `Uploaded`, `Verified`. Replace keeps history of the current file rather than silently losing the previous one. Verify is an explicit action by admissions staff.

Default checklist when the school has not named its own list: birth certificate, previous school leaving certificate, guardian CNIC, photograph.

## Student identity

- Admission number is unique per school and generated by the system. Prefix and digit length come from school settings (working default prefix `CLS`, 4 digits).
- Personal fields: name, gender, date of birth, contact, address, photograph, emergency contact.
- Gender: `Male`, `Female`, `Other`.
- Academic fields: current class, session, previous school information, promotion history, examination history.
- Finance on the profile is read-only and comes from the fee ledger.

## Student status

Live contract:

| Status | Meaning |
|---|---|
| `Active` | Attending. Counted. Included in class lists and fee generation. |
| `Pending` | Admitted but not yet fully active. |
| `Withdrawn` | Left. Kept for history. Excluded from active lists and new fee generation. |

The baseline also names Inactive, Graduated, and Struck off. Those are still product requirements (P1-03) and are not replaced by the addendum. When they are implemented:

- Inactive: temporarily away. Dropped from active counts. Not deleted.
- Graduated: schooling complete. Date, final class, session, final result. History remains.
- Struck off: enrollment ended. Date, reason, academic status, financial status including outstanding fees. History remains.

Every status change stores a reason, a date, and who changed it.

## Guardians and parents

- A student may have more than one parent link. Relationship is `Father`, `Mother`, or `Guardian`. One link may be primary.
- A parent user sees only students linked to them.
- Enrollment should create or reuse the parent user and the link. A student with no parent link is invisible in the parent portal.

## Promotion

Promotion records previous class, new class, session, and date. It does not delete the old class membership from history.

Bulk promotion of a whole class is not a requirement.

## Profile visibility

Parents see only fields the school has approved for them: name, date of birth, class, session, and any promotion timeline or remarks the school chooses to expose. They do not see other students, staff notes that were not approved, or fee totals for the school.
